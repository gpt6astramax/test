# 景深翻页 · 设计总结

音乐库 App 的 UI 原型。这份文档记录它的设计语言和所有可调参数，写正式版时照着搬。

## 1. 一句话

背景永远不动，只有内容在动。翻走的那页不往旁边滑走，而是原地缩小、下沉、变虚，留在后面当新页面的背景。播放器是唯一的例外：它从下面升上来，往下一拉就收走。

## 2. 底色和主题

| | 浅色 | 深色 |
|---|---|---|
| 底色 `--bg` | `#f2f2f0` 浅白 | `#000000` 纯黑 |
| 墨色 `--fg` | `#111214` | `#f2f2f3` |
| 二级文字 `--fg2` | 墨色 62% | 墨色 64% |
| 三级文字、未选中图标 `--fg3` | 墨色 36% | 墨色 38% |
| 分隔线 `--hair` | 墨色 10% | 墨色 14% |
| 浅填充 `--fill` | 墨色 5% | 墨色 8% |
| 玻璃 `--glass` | 白 60% | `rgb(30 30 32)` 55% |
| 收藏的心 `--like` | `#f0467f` | `#ff6b9a` |

- 底色是一块纯色。**任何页面都没有自己的底色，只有内容**，包括播放器：背景永远是上一页的虚化。
- 默认浅色。右上角圆钮切换，新主题从按钮处以圆形铺开（约 820ms）；不支持时全局颜色渐变 0.6s。
- 界面本身是单色的。唯一的颜色来自曲目：每首曲目有一个色相，封面、波形已播放部分、播放按钮、类型标签都用它，写成 `oklch(亮度 彩度 色相)`，浅色主题亮度 .52、彩度 .17，深色主题亮度 .82、彩度 .13。收藏的心是另一个固定的粉色。

## 3. 字体

- 字体栈：`"Jost", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。拉丁字母和数字用 Jost，中文落到系统字体。字体文件随应用打包，不依赖外部字体服务。
- 标题用 300 细体，正文用 400，列表里的曲名用 600。

| 用途 | 字号 / 行高 | 字重 | 字距 |
|---|---|---|---|
| 页面大标题 | 36 / 42 | 300 | 1px |
| 曲目名、音乐人名（大） | 34 / 37 | 300 | 0.4px |
| 小节标题 | 12.5 / 16 | 400 | 2px |
| eyebrow 小标 | 11.5 / 15，全大写 | 400 | 1.6px |
| 列表行标题 | 16 / 21 | 600 | — |
| 列表行副标题 | 13 / 18 | 400 | — |
| 列表行时长 | 12 / 16，等宽字体 | 400 | — |
| 正文 | 15 / 23 | 400 | — |
| 注释 | 12.5 / 19 | 400 | — |

- 数字一律 `tabular-nums`。
- 输入框字号 16，小于它 iPhone 聚焦时会自动放大。

## 4. 布局

- 内容列最宽 460px，居中；左右留白 20px（横屏时取安全区和 20px 的较大者）。
- 页面内各区块间距 28px，区块内标题到内容 12px。
- 页面内容一直铺到屏幕上下边缘，顶部清晰显示在状态栏下面，不做渐隐。需要避让的地方自己减安全区：页面上留白、返回钮、底栏、提示条。
- 没有标题栏。标题是内容最上方的大标题，跟着内容滚走。子页面左上角有一个悬浮的玻璃圆钮（42px）用来返回。
- 圆角：封面 14–20px，列表小封面 8px，按钮和标签全圆。
- 卡片样式几乎不用：列表行没有底色，只有一条分隔线。玻璃只用在浮起来的东西上（返回钮、主题钮、播放条）。

## 5. 景深翻页

页面栈里每个新页都是一个横向手势，向右滑返回。

| 参数 | 值 | 说明 |
|---|---|---|
| 进入时长 | 660ms | 缓动 `cubic-bezier(.2,.86,.24,1)` |
| 进入位移 | 整页从右侧约 17% 屏宽处滑入 | 用库的 `enter()`，是动画不是手势 |
| 内容错开 | 每块延迟 20ms，最多 7 档 | 各块再从右 28px、透明度 0 进来 |
| 后面那页（第 1 层） | 缩到 0.86，下沉 4.5%，模糊 20px，透明度 0.5 | |
| 再后面（第 2 层） | 缩到 0.74，下沉 10%，模糊 40px，透明度 0 | |
| 更深的层 | 不渲染 | `visibility: hidden` |
| 返回的提交点 | 屏幕右侧外 10% | 库的 `overshoot: 0.1` |
| 滑走的内容淡出 | 移动到 80% 屏宽时完全透明 | |
| 末段穿透 | 从 80% 起不再接触摸 | 页面这时已经看不见了，不能再让点按落在它上面；库的默认值是最后 5% |

- 手势有两种驱动，在「我的 → 手势方案」里切换（对之后打开的页面生效）：
  - **原生滚动**（默认）：拖动就是浏览器自己的滚动和吸附。后面两层的缩放、下沉、模糊、透明度，以及顶页内容的淡出，全部绑在顶页的滚动时间线上，每帧不跑 JS。
  - **JS**：触摸事件加弹簧。同样的数值由脚本在每一帧写上去。
- 进入期间不挡触摸：手指可以直接上下滚新页；只有点按等页面到位。
- 每个页面至少能滚 1px，并且把回弹留在自己身上，短页面不会把拖动传给整页。

### 一条规矩：过渡结束的那一刻，什么都不改

过渡刚结束，正是手指在滚刚出现的那一页的时候。在 iOS 上，正被滚动的元素的祖先如果这时改了图层、overflow 或动画，滚动会当场停住：没有惯性，拉过头的回弹直接跳回去。所以：

- 一个页面返回手势需要的东西（淡出动画、图层）在它创建时一次设好，之后不再动。
- 进入只是叠在上面的一段动画，自己放完，什么都不用撤销。
- 滑走的页面留在原地（已经在屏幕外、不接触摸），等到没有手指、也没有滚动之后再真正移除（`lib/quiet.js`）。
- 会被过渡移动的东西（每一层页面、播放器下面的整个界面）一直保有自己的图层（`will-change: transform`），不随过渡来回创建销毁。
- 切页签时，新页签直接出现、自己没有任何过渡；淡出的是盖在它上面的旧页签。

`app/tests/stable.js` 检查这条规矩：在四个场景下（切页签、进页、返回、收起播放器）让手指持续滚动，记录被滚动页面及其所有祖先上的每一处修改（属性、class、内联样式、动画的增减）。两种驱动下都是 0 处。

## 6. 播放器

- 任何时候都从下面升上来，盖住包括底栏在内的一切；往下拉收走。点列表里的任意曲目、点播放条，都是打开它。
- 升到位之后它就是一个独立页面：一直铺到屏幕顶，没有圆角。
- 顶部正中有一条短的暗色线段（两段各 21 × 5，圆头，墨色 60%），静止时向下折成一个浅浅的下箭头（每段转 16°），提示可以往下收；开始往下拉（约 6%）就变直。点它也能收起。可点区域 96 × 40。没有单独的返回或关闭按钮。
- 网页上它是一个纵向的原生滚动手势：跟手、惯性、吸附都是浏览器的。升起用 `enter()`，620ms。
- 内容自己滚动，顶部留白是上安全区 + 50px；滚到顶之后再往下拉，拉动的就是整页。从顶部那条线段上往下拉，不管内容滚到哪里都能直接拉动。
- 和所有页面一样，它没有自己的底色，只有内容。原来屏幕上的整个界面（连同底栏）留在它后面当背景：缩到 0.86、下沉 4.5%、模糊 20px、透明度 0.5，和页面栈里“后面那页”的数值完全一样；往下拉时跟着回到焦点。
- 在播放器里点相似曲目：原地换歌。点音乐人或标签：先收起，再在下面的页签里打开对应页面。

## 7. 底栏（DotTabBar）

以后常用的底栏。网页版是 `app/src/ui/DotTabBar.web.jsx`，自带样式，加上 `glider.js`、`platform.js` 即可搬走；iOS / Android 版是 `app/src/ui/DotTabBar.jsx`，属性相同。

- 只有图标，没有文字。当前页签的图标是墨色，其余是三级灰；当前图标下方有一个 6px 的圆点。
- 高 52px。图标 25px，在这一行里垂直居中。
- 没有背景框、边框和阴影。图标后面有一条只做模糊的胶囊：中间约 44px 高的一条完全模糊（18px），向上下左右各用约 28px 渐渐变清晰，两端是半圆。底栏离屏幕底边至少 26px，模糊在到达底边之前已经完全清晰。
- 整条底栏是一个大的 `<label>`，里面包着隐藏的原生开关：iPhone 上手指点它会触发系统触感。安卓走震动接口，每经过一个页签震一下。
- 圆点就是滑块，由弹簧驱动，不用 CSS 过渡，所以不会瞬移：
  - 点按：弹到点中的页签。
  - 按住拖动：跟着手指走，经过哪个页签就切到哪个；松手弹回到位。
  - 按住时被拉成扁椭圆（约 2.6 倍宽、0.76 倍高）；移动时按速度沿路径拉长压扁。
  - 弹簧参数：按住时刚度 520、阻尼 38；松手后刚度 300、阻尼 22，带一点回弹。
- 再点一次当前页签：回到该页签的第一页；已经在第一页就滚回顶部。
- 切换页签时，离开的那一页用 0.28s 淡出，同时缩到 0.96 并模糊 12px，新页签在它下面直接出现。

用法：

```jsx
<DotTabBar
  tabs={[{ key: 'home', label: '发现', icon: <Icon name="compass" size={25} /> }, …]}
  index={tab}
  onChange={(i) => setTab(i)}
  onReselect={(i) => popToRoot(i)}
/>
```

颜色可以用 CSS 变量覆盖：`--dtb-fg`、`--dtb-muted`、`--dtb-blur`。

## 8. 列表行

尺寸照参考图逐项量出来（参考图是 3 倍图，下面是换算后的 pt），在同样的屏宽下截图对过：封面、文字、时间、心形、分隔线的位置和参考图相差不超过 2 个物理像素（3 倍图，即不到 0.7pt）。

| 元素 | 尺寸 |
|---|---|
| 行高 | 66，封面上下各留 9 |
| 封面 | 48 × 48，圆角 8，一圈细边（分隔线的颜色） |
| 封面到文字 | 12 |
| 曲名 | 16 / 21，半粗（Jost 600），墨色 |
| 音乐人 | 13 / 18，常规，二级灰；和曲名之间 2 |
| 时长 | 12，等宽字体，三级灰；右端离内容列右边缘 48 |
| 心形 | 图标 16（图形本身宽约 12.7），中心离内容列右边缘 18；可点区域 36 × 66 |
| 分隔线 | 1，从文字左缘画到内容列右边缘，不画在封面下面；最后一行没有 |

- 时长和心形比行的正中低 1.5。
- 副标题只有音乐人，不带类型。
- 心形：两个圆瓣，中间一个尖角的 V，底部略圆的尖。空心时是三级灰的 2 粗描边；收藏后实心，粉色。
- 不显示波形和 BPM，这些只在播放器里。
- 点行的任意位置：播放这首并升起播放器。点心：收藏或取消，不打开播放器。
- 正在播放的那一行，曲名用这首曲目的颜色。

## 9. 触感

- 网页：所有按钮都是 `<label>` 包隐藏开关的写法（`Tap` 组件）；开关只在 iPhone 上渲染，不设 tabindex。iPhone 网页一次点按只能震一下，拖动途中不能震。
- iOS / Android：`Tap` 和底栏走 expo-haptics 的选择触感，底栏拖动时每经过一个页签震一下。

## 10. 技术结构

一份 React Native 代码，三个平台：

- **网页**：react-native-web 渲染，Vite 构建，部署的就是它。
- **iOS / Android**：Expo（SDK 58），可以直接用 Expo Go 打开。

页面和页面里的所有内容组件（`screens/`、`ui/parts.jsx`）两端共用，只用 `View`、`Text`、`TextInput` 和下面这些封装好的组件，颜色和字体一律从主题取（`useColors()`、`themed()`），不直接写平台专用的值。和平台绑定的部分各写一份，文件名成对：`X.web.jsx` 给网页，`X.jsx` 给 iOS / Android，打包工具自己挑。

| 成对的文件 | 网页（`.web.jsx`） | iOS / Android（`.jsx`） |
|---|---|---|
| `App` | 入口 `main.jsx` + `index.html` | 入口 `index.js`（`registerRootComponent`） |
| `nav/DepthStackView` | 原生滚动手势 + 滚动时间线（`lib/depth-stack.js`） | `Animated` + `PanResponder`，模糊用 expo-blur |
| `ui/DotTabBar` | `<label>` + 隐藏开关，`glider.js` 的弹簧 | 同一套弹簧参数，触感用 expo-haptics |
| `ui/PlayerSheet` | 纵向的原生滚动手势 | `Animated` + `PanResponder` |
| `ui/Tap` | `<label>` 包隐藏开关 | `Pressable` + expo-haptics |
| `ui/theme` | CSS 变量，切换时圆形铺开 | 主题值放在 context 里，切换时旧纸面盖上来再淡出 |
| `ui/fonts` | CSS 里的 Jost | expo-font 加载 Jost |
| `ui/Icon`、`ui/Cover`、`ui/Wave` | 内联 SVG、canvas、CSS mask | react-native-svg、`View` |
| `ui/Glass`、`ui/Segmented`、`ui/MiniPlayer` | backdrop-filter、弹簧滑块 | expo-blur、`Animated` |

两端共用的数据和算法：`data.js`、`state.js`、`artdata.js`（封面和波形的形状）、`ui/icon-paths.js`、`ui/color.js`（oklch 转 sRGB，原生端用）。

### 在 Expo Go 里打开

电脑和手机连同一个网络，手机装好 Expo Go（要支持 SDK 58）。

```bash
cd depth-music/app
```

```bash
npm install
```

```bash
npx expo start
```


```bash
npm run build
```

## 11. 原生端和网页端不一样的地方

- **后面那页的虚化**：网页是对那一层本身做模糊；原生端是在它上面盖一层 expo-blur，模糊强度跟着翻页进度走。Android 上 expo-blur 默认不做真模糊，只是一层半透明的色调，所以 Android 上后面那页是缩小、下沉、变淡，但不虚。
- **底栏的模糊胶囊**：网页上向四周渐渐变清晰、没有边缘；原生端没法给模糊做渐变遮罩，iOS 上用三层由外到内逐渐加强的胶囊来近似，Android 上是一个半透明胶囊。
- **内容错开进入**：网页上新页的各块依次错开 20ms 进来；原生端整页一起进。
- **主题切换**：网页从按钮处圆形铺开；原生端是旧纸面盖上来再淡出。
- **播放条**：网页上可以左右滑切歌；原生端只有点按。
- **分段切换**：网页上滑块跟手；原生端只有点按。
- **Android 的返回键**：先收播放器，再退一页，在页签第一页时交给系统。

## 12. 还没做的

- 原生端只做过打包检查（iOS 和 Android 的包都能打出来），以及把原生那套代码放进浏览器里跑过全部交互；**没有在真机或模拟器上跑过**，第一次用 Expo Go 打开时可能还有要调的地方。
- 上面那条规矩针对的是 iPhone 上“刚切换就滚会停住”和底栏模糊偶尔掉一下的问题。检查脚本只能证明祖先元素上不再有改动，**iPhone 上的实际效果没有在真机上验证过**。
- 没有音频，播放进度是模拟的。播放进度每秒更新 4 次，不做逐帧动画（一步不到半个像素）：逐帧动画会让主线程每一帧都重绘波形。
- 主屏幕模式下铺满整屏的问题在这台测试手机上没有解决，“我的”里保留了手动开关和屏幕数据（只在网页版显示）。
