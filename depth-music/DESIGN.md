# 景深翻页 · 设计总结

音乐库 App 的 UI 原型。这份文档记录它的设计语言和所有可调参数，写正式版时照着搬。

## 1. 一句话

背景永远不动，只有内容在动。翻走的那页不往旁边滑走，而是原地缩小、下沉、变虚，留在后面当新页面的背景。播放器是唯一的例外：它从下面升上来，往下一拉就收走。

## 2. 底色和主题

| | 浅色 | 深色 |
|---|---|---|
| 底色 `--bg` | `#f2f2f0` 浅白 | `#000000` 纯黑 |
| 墨色 `--fg` | `#111214` | `#f2f2f3` |
| 二级文字 `--fg2` | 墨色 62% | 墨色 64% |
| 三级文字、未选中图标 `--fg3` | 墨色 36% | 墨色 38% |
| 分隔线 `--hair` | 墨色 10% | 墨色 14% |
| 浅填充 `--fill` | 墨色 5% | 墨色 8% |
| 玻璃 `--glass` | 白 60% | `rgb(30 30 32)` 55% |
| 收藏的心 `--like` | `#f0467f` | `#ff6b9a` |

- 底色是一块纯色。**任何页面都没有自己的底色，只有内容**，包括播放器：背景永远是上一页的虚化。
- 默认浅色。右上角圆钮切换，新主题从按钮处以圆形铺开（约 820ms）；不支持时全局颜色渐变 0.6s。
- 界面本身是单色的。唯一的颜色来自曲目：每首曲目有一个色相，封面、波形已播放部分、播放按钮、类型标签都用它，写成 `oklch(亮度 彩度 色相)`，浅色主题亮度 .52、彩度 .17，深色主题亮度 .82、彩度 .13。收藏的心是另一个固定的粉色。

## 3. 字体

- 字体栈：`"Jost", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。拉丁字母和数字用 Jost，中文落到系统字体。字体文件随应用打包，不依赖外部字体服务。
- 标题用 300 细体，正文用 400，列表里的曲名用 600。

| 用途 | 字号 / 行高 | 字重 | 字距 |
|---|---|---|---|
| 页面大标题 | 36 / 42 | 300 | 1px |
| 曲目名、音乐人名（大） | 34 / 37 | 300 | 0.4px |
| 小节标题 | 12.5 / 16 | 400 | 2px |
| eyebrow 小标 | 11.5 / 15，全大写 | 400 | 1.6px |
| 列表行标题 | 16 / 21 | 600 | — |
| 列表行副标题 | 13 / 18 | 400 | — |
| 列表行时长 | 12 / 16，等宽字体 | 400 | — |
| 正文 | 15 / 23 | 400 | — |
| 注释 | 12.5 / 19 | 400 | — |

- 数字一律 `tabular-nums`。
- 输入框字号 16，小于它 iPhone 聚焦时会自动放大。

## 4. 布局

- 内容列最宽 460px，居中；左右留白 20px（横屏时取安全区和 20px 的较大者）。
- 页面内各区块间距 28px，区块内标题到内容 12px。
- 页面内容一直铺到屏幕上下边缘，顶部清晰显示在状态栏下面，不做渐隐。需要避让的地方自己减安全区：页面上留白、返回钮、底栏、提示条。
- 没有标题栏。标题是内容最上方的大标题，跟着内容滚走。子页面左上角有一个悬浮的玻璃圆钮（42px）用来返回。
- 圆角：封面 14–20px，列表小封面 8px，按钮和标签全圆。
- 卡片样式几乎不用：列表行没有底色，只有一条分隔线。玻璃只用在浮起来的东西上（返回钮、主题钮、播放条）。

## 5. 景深翻页

页面栈里每个新页都是一个横向手势，向右滑返回。

| 参数 | 值 | 说明 |
|---|---|---|
| 进入时长 | 660ms | 缓动 `cubic-bezier(.2,.86,.24,1)` |
| 进入位移 | 整页从右侧约 17% 屏宽处滑入 | 用库的 `enter()`，是动画不是手势 |
| 内容错开 | 每块延迟 20ms，最多 7 档 | 各块再从右 28px、透明度 0 进来 |
| 后面那页（第 1 层） | 缩到 0.86，下沉 4.5%，模糊 20px，透明度 0.5 | 模糊怎么做有几种，见下面「后面那页怎么变虚」 |
| 再后面（第 2 层） | 缩到 0.74，下沉 10%，透明度 0 | |
| 更深的层 | 不渲染 | `visibility: hidden` |
| 返回的提交点 | 屏幕右侧外 10% | 库的 `overshoot: 0.1` |
| 滑走的内容淡出 | 移动到 80% 屏宽时完全透明 | |
| 末段穿透 | 从 80% 起不再接触摸 | 页面这时已经看不见了，不能再让点按落在它上面；库的默认值是最后 5% |

- 手势有两种驱动，在「我的 → 手势方案」里切换（对之后打开的页面生效）：
  - **原生滚动**（默认）：拖动就是浏览器自己的滚动和吸附。后面两层的缩放、下沉、透明度、虚化，以及顶页内容的淡出，全部绑在顶页的滚动时间线上，每帧不跑 JS。
  - **JS**：触摸事件加弹簧。同样的数值由脚本在每一帧写上去。
- 进入期间不挡触摸：手指可以直接上下滚新页；只有点按等页面到位。
- 每个页面至少能滚 1px，并且把回弹留在自己身上，短页面不会把拖动传给整页。

### 后面那页怎么变虚

在「我的 → 后面那页怎么变虚」里切换（对之后打开的页面和播放器生效），页面栈和播放器用同一个设置（`lib/depth-mode.js`）。

| 方案 | 做法 |
|---|---|
| 自动（默认） | Chrome / Edge 用毛玻璃罩，其他浏览器用图层滤镜 |
| 毛玻璃罩 | 后面的层只缩小、下沉、变淡（`transform` 和 `opacity`）。虚化是盖在它们上面的一层毛玻璃，半径固定 20px，强弱用 `backdrop-filter: blur(20px) opacity(x)` 里的 `opacity()` 调 |
| 图层滤镜 | 后面的层自己带 `filter: blur()`，半径跟着手指从 20px 变到 0 |
| 不虚化 | 对照用：只缩小、下沉、变淡 |

- 毛玻璃罩的强度不是匀速变的。把罩变薄等于让清晰的画面和模糊的画面叠在一起，清晰的那一份一露出来就能看清；而半径慢慢缩小的模糊大半程都看不清。所以强度按 `1 − k⁴` 走（k 是顶页滑走的进度）：大半程几乎不变，最后一段才散掉。两种方案停在半路的截图对比过，看起来接近。
- 毛玻璃罩的强弱用的是它自己 `backdrop-filter` 里的 `opacity()`，不是这个元素的 `opacity`。Chromium 里量过，两种写法效果一样（见第 7 节的表）；Safari 上没有量，所以统一用专门的 `opacity()`。
- 原生端（iOS / Android）本来就是这个思路：在后面那页上盖一层 expo-blur。

### 跟手不掉帧：跟着手指动的东西必须在合成线程上

手指拖动的滚动由浏览器的合成线程执行，不等页面脚本。后面那页、底栏这些跟着动的东西，只有它们的动画也在合成线程上跑，才和手指同一帧。否则每一帧都要主线程送，主线程一忙就落在手指后面：手指下那页是顺的，后面跟着的东西一顿一顿，看起来就是掉帧。Edge 上“跟手时掉帧严重”就是这个原因，量出来有三处，各自独立：

| 原因 | 后果 | 改法 |
|---|---|---|
| 页面停在原位时，正好在滚动时间线的终点 | Chromium 把停在终点的动画当成已结束，不交给合成线程，之后也不再尝试。所有跟随动画都留在主线程 | 手势库在内容后面放 1px 的尾巴，原位离终点差 1px；关键帧从 99% 起保持原位的样子（`99%,100%`） |
| 关键帧里有 `filter: blur()` | 整段动画连同里面的 `transform`、`opacity` 都回到主线程 | 毛玻璃罩：关键帧里只剩 `transform`、`opacity` 和罩的 `opacity()` |
| 进入时，脚本动画和滚动驱动动画叠在同一个元素的同样属性上 | 被盖住过一次的滚动驱动动画，此后一直留在主线程 | 进入的脚本动画跑完后停在终点（`fill: 'forwards'`），这时再绑时间线，最后取消脚本动画 |

`app/tests/compositor.js` 检查这件事：让推入的页面、然后是播放器，用一次平滑滚动离开，途中把主线程卡住 900ms，从录屏（合成线程画出的帧）里看这段时间后面那页和底栏还动不动。

| 方案 | 推入页面：后面那页 | 播放器：下面那层 | 播放器：底栏 |
|---|---|---|---|
| 毛玻璃罩 | 跟着动 | 跟着动 | 跟着动 |
| 不虚化 | 跟着动 | 跟着动 | 跟着动 |
| 图层滤镜（对照） | 冻住，主线程恢复后才动 | 冻住 | 跟着动 |

这些只在无头 Chromium 153 里量过。真实的 Edge 上是否顺了，要在设备上看；Safari 的合成线程规则没有量，所以 Safari 默认还用原来的图层滤镜。

### 一条规矩：过渡结束的那一刻，什么都不改

过渡刚结束，正是手指在滚刚出现的那一页的时候。在 iOS 上，正被滚动的元素的祖先如果这时改了图层、overflow 或动画，滚动会当场停住：没有惯性，拉过头的回弹直接跳回去。所以：

- 一个页面返回手势需要的东西（淡出动画、图层）在它创建时一次设好，之后不再动。
- 进入只是叠在上面的一段动画，自己放完，什么都不用撤销。
- 滑走的页面留在原地（已经在屏幕外、不接触摸），等到没有手指、也没有滚动之后再真正移除（`lib/quiet.js`）。
- 会被过渡移动的东西（每一层页面、播放器下面的整个界面）一直保有自己的图层（`will-change: transform`），不随过渡来回创建销毁。
- 切页签时，新页签直接出现、自己没有任何过渡；淡出的是盖在它上面的旧页签。

- 进入结束时要改的只有后面的层和毛玻璃罩（把它们绑到时间线上），这时没有人在滚它们。

`app/tests/stable.js` 检查这条规矩：在四个场景下（切页签、进页、返回、收起播放器）让手指持续滚动，记录被滚动页面及其所有祖先上的每一处修改（属性、class、内联样式、动画的增减）。两种驱动下都是 0 处。同一个脚本还检查底栏的毛玻璃在播放器升起、下拉、收起的全过程中，祖先元素上始终没有滤镜。

## 6. 播放器

- 任何时候都从下面升上来，盖住页面和底栏；往下拉收走。点列表里的任意曲目、点播放条，都是打开它。
- 升到位之后它就是一个独立页面：一直铺到屏幕顶，没有圆角。
- 顶部正中有一条短的暗色线段（两段各 21 × 5，圆头，墨色 60%），静止时向下折成一个浅浅的下箭头（每段转 16°），提示可以往下收；开始往下拉（约 6%）就变直。点它也能收起。可点区域 96 × 40。没有单独的返回或关闭按钮。
- 网页上它是一个纵向的原生滚动手势：跟手、惯性、吸附都是浏览器的。升起用 `enter()`，620ms。
- 内容自己滚动，顶部留白是上安全区 + 50px；滚到顶之后再往下拉，拉动的就是整页。从顶部那条线段上往下拉，不管内容滚到哪里都能直接拉动。
- 和所有页面一样，它没有自己的底色，只有内容。原来屏幕上的页面留在它后面当背景：缩到 0.86、下沉 4.5%、模糊 20px、透明度 0.5，和页面栈里“后面那页”的数值完全一样；往下拉时跟着回到焦点。虚化的做法也跟页面栈用同一个设置（毛玻璃罩 / 图层滤镜 / 不虚化）。
- **播放器升起时，底栏不动，被播放器自然遮住，毛玻璃不丢。**
  - 底栏留在原位，在播放器下面一层。播放器对它什么都不做：不位移、不缩放、不变淡、不关它的毛玻璃、不加 `inert`、不挂动画。
  - 播放器自己带一层毛玻璃（和播放器一样大，跟着它一起动，模糊 20px，没有底色）。升起时这层玻璃和播放器的内容从底栏上面盖过去；收起时播放器的上沿经过底栏，底栏原样露出来。
  - 这层玻璃是播放器里单独的一个元素，垫在内容后面，不是播放器的容器本身：一个带毛玻璃的元素里面如果再放别的毛玻璃（比如以后加玻璃按钮），Safari 会把它整个压成一张图来画。
  - 后面那一页照旧整体缩小、下沉、变淡、变虚；底栏不在那一层里，所以不跟着缩小。
  - 播放器在上面时，触摸落在播放器上，到不了底栏；键盘焦点落到底栏上会被放开。
  - 之所以什么都不做：只要对底栏或它的祖先元素动了手，就有让毛玻璃失效的机会（见下面「底栏在返回时掉毛玻璃」和第 7 节「毛玻璃和透明度」）；普通子页面从来不碰底栏，底栏在那里也从来没出过问题。
- 在「我的 → 播放器升起时的底栏」里还能切到别的做法（下次打开播放器时生效），用来对照：

  | 方案 | 对底栏做了什么 | 效果 |
  |---|---|---|
  | 不动，被播放器自然遮住（默认） | 什么都不做 | 见上 |
  | 不动，原地变虚 | 什么都不做 | 一层盖住全屏的毛玻璃罩跟着播放器变浓，底栏和页面一起原地变虚；播放器收起时一起变清楚。这种方案下播放器固定用毛玻璃罩 |
  | 不动，一直显示 | 什么都不做 | 底栏留在播放器前面，和普通子页面里一样；点页签会先收起播放器 |
  | 下沉离开 | 位移 | 往下沉出屏幕；播放器往下拉过约三分之一后跟着手指回来 |
  | 跟着上升 | 位移 | 贴着播放器的上沿，和播放器同速被顶上去，从屏幕顶部出去 |
  | 向左离开 | 位移 | 往左滑出屏幕 |
  | 原地淡出 | 改它的浓淡 | 不移动；图标和圆点变淡，毛玻璃用它自己 `backdrop-filter` 里的 `opacity()` 变淡 |
  | 留下，去掉毛玻璃 | 放进后面那一层 | 和页面一起缩小退后，它自己的毛玻璃在这期间关掉 |
  | 留下，保留毛玻璃 | 放进后面那一层 | 和页面一起缩小退后 |

  - 会位移的三种：底栏和它的祖先元素只用 `transform` 移动，不碰 `opacity` 和 `filter`。播放器一离开屏幕，挂在底栏上的动画和样式就立刻撤掉，不等到“安静”之后。
  - “回到焦点”的状态是完全没有滤镜（`filter: none`），不是“模糊 0”。
  - iOS / Android 端目前只有「下沉离开」一种。
- 在播放器里点相似曲目：原地换歌。点音乐人或标签：先收起，再在下面的页签里打开对应页面。
- 检查脚本，都在两种手势驱动下跑：
  - `app/tests/blur-scan.js`：默认方案下，底栏是不是**在每一个状态里**要么被盖住、要么在正常模糊。在底栏正后面放一组清晰的竖条纹，然后：播放器升起（所有动画放慢到十分之一，约每 90ms 看一次），手指把播放器一步步拉下来（每 12px 看一次；播放器的上沿经过底栏的那一段每 2px 看一次），松手后 2 秒内尽快连续看（吸附、离开、清理）。一共约 200 个状态。每个状态里，胶囊内部都不能露出条纹：底栏在显示时由它自己的毛玻璃模糊掉，被盖住时由播放器的玻璃模糊掉；露出条纹就说明底栏在那里却没有模糊。结果：约 50 个状态底栏在显示，约 30 个状态播放器的上沿正划过它，约 140 个状态被盖住；胶囊里的条纹始终不超过 4%。两种虚化做法、两种手势驱动都一样。
  - `app/tests/chrome-modes.js`：九种方案下，底栏在播放器升起、拉到一半、收起后的位置；全过程每一帧里，显示着的毛玻璃有没有落在带滤镜、透明度小于 1 或带透明度动画的元素里；以及这期间对底栏做过什么（前三种必须是“什么都没做”：没有任何属性、样式、节点、动画的变化）。
  - `app/tests/glass.js`：从截图的像素里量毛玻璃是不是真的在模糊。分两部分：底栏的毛玻璃（静止、进页、返回、切页签、各种方案下播放器的升起和收起），以及各种虚化方案下后面那页是不是真的虚了。

### 底栏在返回时掉毛玻璃：查到了什么

现象：播放器收起、回到页面的那一小段，原地不动的底栏没有毛玻璃，过一会儿才恢复。普通子页面里底栏一直正常，哪怕它后面同样是变虚的上一页。

**原因在之前那几种“底栏留在原地”的做法本身**，用 `blur-scan.js` 量出来：

| 之前的做法 | 量到的情况 |
|---|---|
| 留下，去掉毛玻璃 | 播放器期间底栏的毛玻璃被**故意关掉**，而且要等播放器收起后的清理才重新打开。松手后还有约 0.7 秒，底栏已经回到原位、页面也清楚了，胶囊里却没有模糊。这就是“返回的短暂时间失去毛玻璃” |
| 原地淡出 | 播放器在上面和被往下拉的全程里，底栏的毛玻璃被**故意调淡**（65 个下拉状态里有 60 个模糊不足） |
| 留下，保留毛玻璃 | 底栏在后面那一层里，跟着页面缩小、下沉，不是“不动” |

关掉和调淡，都是当初以为“毛玻璃不能叠毛玻璃”才加的。这个前提是错的：子页面里底栏的毛玻璃一直叠在变虚的上一页上面，两者都正常。所以正确的做法就是对底栏什么都不做，让播放器自己去盖住它。

查的过程中确认的另外几件事：

- 无头 Chromium 里，子页面返回和播放器收起两条路径、两种虚化方案下，只要不去关它，底栏的胶囊都在模糊。
- Safari 的实现和 Chromium 不同（读 WebKit 源码）：“隔离组”是把那一层整体栅格化；触发条件是透明度小于 1、滤镜、遮罩、`clip-path`、混合模式、`backdrop-filter` 本身和这些属性的 `will-change`，位移不在其中；滚动驱动的位移、透明度、滤镜动画在另一个进程里跑。WebKit 的缺陷库里还有几条没关的相关问题（219729、265028、298709）。这些都是“对底栏动手”才会碰上的风险，默认做法不碰底栏，就都绕开了。
- 清理时曾经多写了一次底栏的 `class`（`classList.remove()` 一个不存在的类名，也会重写属性）。已经去掉。
- 真机对照页：部署地址后面加 `glass-return.html`，把对底栏做过的每件事各做成一格，可以在手机上看哪一项会让毛玻璃失效。默认方案里底栏自己什么都不加；它上面有播放器的玻璃经过，对应其中“上面再盖一层毛玻璃”的那一格。


## 7. 底栏（DotTabBar）

以后常用的底栏。网页版是 `app/src/ui/DotTabBar.web.jsx`，自带样式，加上 `glider.js`、`platform.js` 即可搬走；iOS / Android 版是 `app/src/ui/DotTabBar.jsx`，属性相同。

- 只有图标，没有文字。当前页签的图标是墨色，其余是三级灰；当前图标下方有一个 6px 的圆点。
- 高 52px。图标 25px，在这一行里垂直居中。
- 没有底色、边框和阴影。图标后面是一条只做模糊的胶囊（18px），大小就是底栏这一行本身（52 高，两端半圆），模糊均匀铺到边缘，边缘是清晰的。
- 可选的 `feather` 属性：改成向四周渐渐变清晰、没有边缘的样子（中间约 44px 高完全模糊，向外约 28px 渐清；这时底栏离屏幕底边至少留 26px）。
- 整条底栏是一个大的 `<label>`，里面包着隐藏的原生开关：iPhone 上手指点它会触发系统触感。安卓走震动接口，每经过一个页签震一下。
- 圆点就是滑块，由弹簧驱动，不用 CSS 过渡，所以不会瞬移：
  - 点按：弹到点中的页签。
  - 按住拖动：跟着手指走，经过哪个页签就切到哪个；松手弹回到位。
  - 按住时被拉成扁椭圆（约 2.6 倍宽、0.76 倍高）；移动时按速度沿路径拉长压扁。
  - 弹簧参数：按住时刚度 520、阻尼 38；松手后刚度 300、阻尼 22，带一点回弹。
- 再点一次当前页签：回到该页签的第一页；已经在第一页就滚回顶部。
- 切换页签时，离开的那一页用 0.28s 淡出，同时缩到 0.96 并模糊 12px，新页签在它下面直接出现。

### 毛玻璃和透明度

毛玻璃（`backdrop-filter`）只看得到和它在同一个“隔离组”里、位于它后面的内容。下面这些都会让一个元素自成一个隔离组：

- 带 `filter`（哪怕是什么都不改的 `brightness(1)`）；
- `opacity` 小于 1（0.99 也算）；
- 带 `opacity` 动画，或者 `will-change: opacity`。Chrome / Edge 里哪怕数值一直是 1 也算。

在一个最小的页面上逐项量过（条纹背景上放一条毛玻璃，从截图里读胶囊内条纹的强度，0 是全糊，1 是完全没糊）：

| 加在哪 | 加了什么 | 胶囊里的条纹 | 结果 |
|---|---|---|---|
| — | 什么都不加 | 0.00 | 糊 |
| 毛玻璃自己 | `opacity: .5` | 0.50 | 半糊，正常的变淡 |
| 毛玻璃自己 | 透明度动画，数值一直是 1 | 0.00 | 糊 |
| 毛玻璃自己 | `backdrop-filter: blur() opacity(.5)` | 0.50 | 半糊，和上面一样 |
| 外面一层 | `opacity: .5` 或 `.99` | 1.00 | **失效** |
| 外面一层 | 透明度动画，数值一直是 1 | 1.00 | **失效** |
| 外面一层 | `will-change: opacity` | 1.00 | **失效** |
| 外面一层 | `filter: brightness(1)` | 1.00 | **失效** |
| 外面一层 | `transform`，或位移动画 | 0.00 | 糊 |

也就是说，在 Chromium 里：毛玻璃自己怎么变淡都行，出问题的是它**外面的任何一层**。底栏的胶囊是底栏里的一个子元素，所以底栏本身和装它的容器都算“外面一层”。

这张表做成了一个可以在手机上直接看的页面：部署地址后面加 `glass-test.html`（源文件 `app/static/glass-test.html`）。在 iPhone Safari 和 Edge 上打开，哪几格能看到清晰的条纹，哪几格就是失效。

底栏如果自己（或它的容器）成了隔离组，组里它后面什么都没有，毛玻璃就取不到画面，显示成透明。上一版里，底栏的每一种离开方式都在关键帧里写了透明度：三种是淡出，「跟着上升」是一段数值一直为 1 的透明度。结果是 Edge 上全坏，Safari 上只有「跟着上升」正常（由此推断 Safari 不把数值不变的透明度动画算进去；Chromium 里量过，算）。

所以规矩是：

- 底栏和它所有的祖先元素，只用 `transform` 移动。不设 `opacity`，不设 `filter`，不放透明度动画，也不写 `will-change: opacity`。
- 要让底栏变淡，设 `--dtb-o`（1 到 0）：图标和圆点各自变淡，毛玻璃用自己 `backdrop-filter: blur() opacity()` 里的 `opacity()` 变薄。这些都不在毛玻璃的祖先上。
- 其他浮着的毛玻璃（玻璃圆钮、播放条、毛玻璃罩）同理。

这条规矩是在无头 Chromium 里用像素量出来的（`app/tests/glass.js` 量的是整个 App，上面那张表量的是最小页面）。iPhone Safari 上没有验证，用上面那个对照页在真机上看。

用法：

```jsx
<DotTabBar
  tabs={[{ key: 'home', label: '发现', icon: <Icon name="compass" size={25} /> }, …]}
  index={tab}
  onChange={(i) => setTab(i)}
  onReselect={(i) => popToRoot(i)}
/>
```

可以用 CSS 变量覆盖：`--dtb-fg`（当前图标和圆点）、`--dtb-muted`（其余图标）、`--dtb-blur`（模糊半径，默认 18px）、`--dtb-o`（整条的浓淡，1 到 0）。

## 10. 技术结构

一份 React Native 代码，三个平台：

- **网页**：react-native-web 渲染，Vite 构建，部署的就是它。
- **iOS / Android**：Expo（SDK 58），可以直接用 Expo Go 打开。

页面和页面里的所有内容组件（`screens/`、`ui/parts.jsx`）两端共用，只用 `View`、`Text`、`TextInput` 和下面这些封装好的组件，颜色和字体一律从主题取（`useColors()`、`themed()`），不直接写平台专用的值。和平台绑定的部分各写一份，文件名成对：`X.web.jsx` 给网页，`X.jsx` 给 iOS / Android，打包工具自己挑。

| 成对的文件 | 网页（`.web.jsx`） | iOS / Android（`.jsx`） |
|---|---|---|
| `App` | 入口 `main.jsx` + `index.html` | 入口 `index.js`（`registerRootComponent`） |
| `nav/DepthStackView` | 原生滚动手势 + 滚动时间线（`lib/depth-stack.js`） | `Animated` + `PanResponder`，模糊用 expo-blur |
| `ui/DotTabBar` | `<label>` + 隐藏开关，`glider.js` 的弹簧 | 同一套弹簧参数，触感用 expo-haptics |
| `ui/PlayerSheet` | 纵向的原生滚动手势 | `Animated` + `PanResponder` |
| `ui/Tap` | `<label>` 包隐藏开关 | `Pressable` + expo-haptics |
| `ui/theme` | CSS 变量，切换时圆形铺开 | 主题值放在 context 里，切换时旧纸面盖上来再淡出 |
| `ui/fonts` | CSS 里的 Jost | expo-font 加载 Jost |
| `ui/Icon`、`ui/Cover`、`ui/Wave` | 内联 SVG、canvas、CSS mask | react-native-svg、`View` |
| `ui/Glass`、`ui/Segmented`、`ui/MiniPlayer` | backdrop-filter、弹簧滑块 | expo-blur、`Animated` |

两端共用的数据和算法：`data.js`、`state.js`、`artdata.js`（封面和波形的形状）、`ui/icon-paths.js`、`ui/color.js`（oklch 转 sRGB，原生端用）。

## 11. 原生端和网页端不一样的地方

- **后面那页的虚化**：网页在 Chrome / Edge 里是盖一层毛玻璃罩，在其他浏览器里是对那一层本身做模糊；原生端是在它上面盖一层 expo-blur，模糊强度跟着翻页进度走。Android 上 expo-blur 默认不做真模糊，只是一层半透明的色调，所以 Android 上后面那页是缩小、下沉、变淡，但不虚。
- **底栏的模糊胶囊**：网页上向四周渐渐变清晰、没有边缘；原生端没法给模糊做渐变遮罩，iOS 上用三层由外到内逐渐加强的胶囊来近似，Android 上是一个半透明胶囊。
- **内容错开进入**：网页上新页的各块依次错开 20ms 进来；原生端整页一起进。
- **主题切换**：网页从按钮处圆形铺开；原生端是旧纸面盖上来再淡出。
- **播放条**：网页上可以左右滑切歌；原生端只有点按。
- **分段切换**：网页上滑块跟手；原生端只有点按。
- **Android 的返回键**：先收播放器，再退一页，在页签第一页时交给系统。

## 12. 还没做的

- 原生端只做过打包检查（iOS 和 Android 的包都能打出来），以及把原生那套代码放进浏览器里跑过全部交互；**没有在真机或模拟器上跑过**，第一次用 Expo Go 打开时可能还有要调的地方。
- 上面那条规矩针对的是 iPhone 上“刚切换就滚会停住”和底栏模糊偶尔掉一下的问题。检查脚本只能证明祖先元素上不再有改动，**iPhone 上的实际效果没有在真机上验证过**。
- 播放器升起时底栏不动、被播放器自带的毛玻璃遮住：在无头 Chromium 里逐状态量过（`blur-scan.js`），对底栏本身的操作是零，**但没有在真机上验证过**。
- Edge 上跟手掉帧的三个原因是在无头 Chromium 里量出来并改掉的，检查脚本也都通过，但**没有在真实的 Edge 上看过效果**。
- 底栏毛玻璃变透明的原因同样是在无头 Chromium 里用像素量出来的。**iPhone Safari 上八种底栏方案和三种虚化方案都没有验证过**。
- 触控板上手指停住不动时，手势库不再自己把页面送走（等浏览器的 `scrollend`）。这一条测试环境里测不到，是按浏览器的行为写的。
- 没有音频，播放进度是模拟的。播放进度每秒更新 4 次，不做逐帧动画（一步不到半个像素）：逐帧动画会让主线程每一帧都重绘波形。
- 主屏幕模式下铺满整屏的问题在这台测试手机上没有解决，“我的”里保留了手动开关和屏幕数据（只在网页版显示）。
